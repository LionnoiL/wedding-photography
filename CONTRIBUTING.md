# Домовленості команди

Короткі правила, щоб код був однаковим у всіх. Тримаймося їх у кожній секції.

## Структура файлів

Файли для всіх секцій **уже створені** - нові не додаємо. Кожен працює у своїх
файлах для своєї секції:

- **Розмітка** - свій партіал у `src/partials/` (напр. `portfolio.html`). Уже
  підключений в `index.html` через `<load src="./partials/..." />`.
- **Стилі** - свій файл у `src/css/` (напр. `portfolio.css`). Уже підключений
  через `@import` у `src/css/styles.css`.
- Один блок = одна секція = свій партіал + свій css-файл. Чужі файли не чіпаємо.

Нові файли додаватимемо пізніше - коли перейдемо до функціоналу на JS.

## HTML

- Верстка **семантична** (HTML5) і **валідна** - перевіряємо через
  [W3C Validator](https://validator.w3.org/).
- В HTML прописуємо тільки класи; **інлайн-стилів немає**.
- Іконки та лого - SVG через спрайт (уже додані у `src/img/sprite.svg`):
  `<svg><use href="../img/sprite.svg#icon-name"></use></svg>`.
- Обгортка ширини - готовий клас `.container`, не дублюємо його логіку.

## Форматування коду

- Форматуємо **Prettier** перед комітом - конфіг у репозиторії, налаштування не
  міняємо.

## Зображення

- Статичні зображення (ті, що **не приходять з API**) зберігаємо у форматі
  **WebP**.
- **Обов'язково** додаємо версію для ретини (`@2x`) через `srcset`:
  ```html
  <img
    class="portfolio__image"
    src="./img/portfolio/photo.webp"
    srcset="./img/portfolio/photo.webp 1x, ./img/portfolio/photo@2x.webp 2x"
    alt=""
  />
  ```
- Кладемо у `src/img/` + папка з назвою секції, напр. `src/img/portfolio/`.
- Зображення з API форматуємо/оптимізуємо на боці бекенду, у репозиторій не
  додаємо.
- Поки виклики API ще не підключені - робимо верстку **повністю** (усі елементи
  на місці, щоб команда бачила готовий вигляд). Замість зображень з API
  використовуємо **мок** (напр. `mock_portfolio.png`).

## CSS-нейминг - BEM або наближений

Строго БЕМ не вимагаємо - головне тримати єдину логіку й читабельні імена:

- Блок: `.portfolio`
- Елемент: `.portfolio__title`, `.portfolio__list`, `.portfolio__item`
- Модифікатор: `.portfolio__filter--active`
- Префікс елемента = ім'я блоку (секції).

## Кольори - тільки змінні з `base.css`

Нові кольори **не додаємо**. Використовуємо наявні змінні:

- Текст: `--color-neutral-darkest`, `--color-neutral-dark`, `--color-neutral` …
- Акцент / кнопки: `--color-curious-blue`, ховер - `--color-curious-blue-dark`.
- Фони секцій: `--color-scheme-1-background` (білий) /
  `--color-scheme-2-background` (кремовий).

Якщо потрібної змінної немає - спочатку **перевіряємо**, що серед наявних у
`base.css` справді немає підхожої, і лише тоді додаємо нову туди (а не
хардкодимо значення в css секції).

## Шрифти

- `--font-family` - Mulish (основний текст, кнопки).
- `--second-family` - Cormorant (заголовки).

## Адаптив - mobile-first

Базові стилі пишемо під мобільний, далі розширюємо через `min-width`. Три
брейкпоінти:

- база: 320-375
- `@media (min-width: 768px)` - планшет
- `@media (min-width: 1440px)` - десктоп

## Робочий процес

- Одна задача = один issue на
  [дошці проєкту](https://github.com/users/LionnoiL/projects/2).
- Прямий пуш у `main` заборонений - тільки через PR з рев'ю.

## Коли зʼявляється нова задача

1. Береш issue на дошці й переводиш його в статус **In progress** (щоб решта
   бачила, що задача зайнята).
2. Оновлюєш свою локальну `main`: `git checkout main && git pull`.
3. Створюєш гілку від `main` під цю задачу: `git checkout -b feat/portfolio`
   (назва - коротко про суть задачі).
4. Працюєш **тільки у своїх файлах** секції; комітиш зрозумілими повідомленнями.
5. Пушиш гілку й відкриваєш **Pull Request** у `main`, прив'язуєш його до issue
   (`Closes #<номер>`).
6. У PR додаєш у **Reviewers** тимліда та ще кількох учасників команди - щоб усі
   долучались до код-рев'ю.
7. Чекаєш **мінімум одне рев'ю**. Після апруву - мерж через **Squash and merge**
   (єдиний дозволений спосіб); гілка видаляється автоматично.
8. Issue переходить у **Done** автоматично після мержу PR.
